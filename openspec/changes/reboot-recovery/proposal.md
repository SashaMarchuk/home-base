## Why
After the machine rebooted, about twenty session tabs were gone at once. An orchestrator had to write a snapshot by hand (per tab: tty, window and group, profile, model, session id, cwd, status, open question, unsent draft) and a one-off script that reopened each session with its resume line and a message re-asking its open question, one window per group, skipping sessions already running. That has to be part of the terminal helpers.

The same reboot showed a bug: ttys are reused, and the text `term.sh survey` printed the registry's session id by tty alone, so a fresh session on a reused tty was listed as an old, dead one. Freeze also updated every open entry of a tty, so it could close a dead session's entry together with the new one.

## What Changes
- New HOME-460: the text survey prints the registry's session id only while the entry names that tab and that process (the test `survey --json` already uses), else `-`; freeze marks and closes a registry entry by tty and session id, never another entry of a reused tty.
- HOME-302 as written, fixed in `survey --json`: a stale registry entry no longer gives a tab its id, resume line, group or role also when no session file is found for the live process.
- New HOME-461, HOME-462 and HOME-467: `term.sh reconcile [--dry-run]` marks an open entry as `lost: <time>` (not closed) when its process is gone and its tab is gone or no longer runs it (a window restored with the same tab ids and fresh shells counts as gone), moving its tty, tab and pid to `lost_tty`, `lost_tab` and `lost_pid`, so no tty lookup matches it again. One signal, unreadable tabs or processes, or no live tab at all mark nothing. It is idempotent and prints one line per change. `survey`, `status` and `finished` stay read only and never run it; `adopt` and `reopen` run it first.
- New HOME-463 and HOME-468: `term.sh adopt <tty>... [--issue N] [--repo R] [--group G]` and `adopt --all` record live tabs this home did not open, typing nothing, with `adopted: true`, so every protection of an adopted tab stays (`close` and `park` need `--adopt`, `finished` keeps it).
- HOME-153 is changed: `adopt --issue` records the issue the owner named at once, because adopt types and closes nothing.
- New HOME-464, HOME-465 and HOME-469: `term.sh reopen [--lost | <session id>...] [--dry-run] [--message TEXT]` reopens lost sessions with their recorded resume lines, one window per group in `term.groups` order (the window logic of open and thaw), with one message (a re-ask of the open question when the run's comment holds one, else a restart note), skipping sessions already running, Codex entries and entries with no resume line.
- New HOME-470 to HOME-474 (after review): adopt follows a session resumed by hand in its own tab; `term.sh forget <session id>` drops a lost entry; reopen skips entries whose issue is closed, finished, released or taken over and never reopens one unchecked; one reopen at a time (the freeze and thaw lock, and a reservation only while the entry is still lost); the profile comes from the process's `CLAUDE_CONFIG_DIR`, adopt says when a profile cannot be passed, and reopen rebuilds a missing or partial resume line from the recorded profile and model only.
- New HOME-466: `term.sh regroup [--dry-run]` prints which registered tabs are outside their group's window. The iTerm2 AppleScript dictionary has no move for a tab, so regroup moves nothing and says so.

## Impact
- `scripts/term/recover.sh` (new, sourced by `term.sh`), `scripts/term/term.sh` (survey, resolve, worker count, dispatch, usage header, `be_tabs` reports an unreadable terminal), `scripts/term/sessions.sh` (`live_entry`), `scripts/term/freeze.sh`, `scripts/term/thaw.sh` (a reopened entry is no longer lost), the fake terminal (`tabs-fail`), `scripts/tests/recover.test.sh` and `sessions.test.sh`, README, the `orchestrate` skill (section 6).
- New registry fields: `lost`, `lost_tty`, `lost_tab`, `lost_pid`; on adopted entries `repo`, `profile`, `model`, `group`, `group_from`, `window`.
